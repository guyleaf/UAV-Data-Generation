# Dataset
To give the developers an overall picture for dataset, we explain the structure for each type of datasets.

## Weather dataset
!!! info "Info: Recommended weather names"
    **clear**, **cloudy**, **foggy**, **rainy**, **snowy** 

A weather dataset must follow the layout below.

```title="The folder structure of a weather dataset"
dataset/
    clear/
        ...
    cloudy/
        ...
    ...       # Other weathers.
```

If the dataset need conversion, such as different names, then we recommend like this below.

```title="The folder structure of a weather dataset"
dataset/
    original/
        clear/
            ...
        cloudy/
            ...
        ...       # Other weathers.
    dataset/      # After conversion
```

## UAV/COCO dataset
### Images folder
After preparing background images, the images folder must follow the layout below across all generation stages.

Including **foregrounds**, **backgrounds**, **harmonized**, **stylized_\***, **images** folder.

```title="The folder structure of the images folder"
images/
    dataset_1/
        clear/
            ...
        cloudy/
            ...
        ...       # Other weathers.
    dataset_1_fake_style/
    dataset_2/
    dataset_2_fake_style/
```

If there are some fake images (transformed from clear/cloudy images), it will be in another folder, naming like **dataset_1_fake_style**.

### Annotations folder
All annotation files will follow [COCO format](https://cocodataset.org/) of object detection.

* `foreground.json`: annotations of foreground images, [generated by blender](../getting-started/uav-generation.md#running-with-the-demo-config).
* `all.json`: annotations of all final images with weather captions, after [post-processing](../getting-started/post-processing.md#post-processing).
* `train.json,val.json`: annotations of final images with weather captions, split from `all.json`, after [post-processing](../getting-started/post-processing.md#post-processing).
